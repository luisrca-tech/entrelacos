## Provider facts that affect the design

Asaas Checkout supports hosted Pix/card collection, split, external references and callbacks. Checkout creation and success redirects do not establish settlement. Validate the exact request schema and the association between checkout and generated payments in sandbox. [Checkout](https://docs.asaas.com/docs/checkout-asaas), [Checkout reference](https://docs.asaas.com/reference/create-new-checkout).

Asaas split percentages apply to the charge's net value after processing fees. The issuing account retains the undistributed net balance. Proposed flow: create the checkout in the couple's account and direct only the agreed commission to the platform wallet. Commercial approval must confirm this account model and responsibility allocation. [Checkout split](https://docs.asaas.com/docs/checkout-com-split-de-pagamento), [Split rules](https://docs.asaas.com/docs/split).

The parent account must be PJ. Public documentation lists an initial evaluation allowance of 10 subaccounts, up to BRL 2,000 in issued charges per subaccount, and up to 60 days starting with the first production subaccount. Verify the actual account agreement; do not start this clock through incidental production testing. [Subaccounts](https://docs.asaas.com/docs/criacao-de-subcontas).

BaaS requires prior alignment with Asaas and provider identification in the approved customer journey. Continued subaccount key management after evaluation is restricted to the approved BaaS model or specified same-CNPJ-prefix branch arrangements. An ordinary account or a working evaluation key does not establish long-term authorization for unrelated couples. [BaaS](https://docs.asaas.com/docs/cria%C3%A7%C3%A3o-de-subcontas-baas), [Subaccount keys](https://docs.asaas.com/docs/gerenciamento-de-chaves-de-api-de-subcontas).

Onboarding can return document-specific `onboardingUrl` values. Prefer provider-hosted document/selfie collection. If an approved flow requires API document uploads instead, record the additional private-data handling before implementing it; never use the public gift-image bucket for KYC. [Onboarding](https://docs.asaas.com/docs/onboarding-e-envio-de-documentos-via-link).

Webhook authentication uses the configured secret in `asaas-access-token`; it is separate from the API key. Do not invent a Stripe-style HMAC signature. Persist authenticated events before returning success and deduplicate delivery IDs. [Webhook receiver](https://docs.asaas.com/docs/receba-eventos-do-asaas-no-seu-endpoint-de-webhook).

`CHECKOUT_PAID` concerns checkout completion. `PAYMENT_CONFIRMED` and `PAYMENT_RECEIVED` distinguish confirmed payment from available funds; refunds, disputes and split outcomes need their own processing. [Checkout events](https://docs.asaas.com/docs/eventos-para-checkout), [Payment events](https://docs.asaas.com/docs/webhook-para-cobrancas).

These are documentation facts checked on 2026-10-12, not evidence that the user's account has the corresponding capability. Recheck exact endpoint schemas and account restrictions during the integration spike.
